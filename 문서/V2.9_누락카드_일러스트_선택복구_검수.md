# YGO STUDIO V2.9 — 누락 카드·일러스트 선택적 복구

## 목표
V2.8에서 연결 진단한 YDK 카드 ID를 기준으로 동일 GitHub Pages origin의 **통합 카드 렌더러(IndexedDB)**와 **이미지 연구소(localStorage)**를 읽기 전용 조회해, 공통 카드·일러스트 보관함에 필요한 신규 자료만 선별적으로 가져온다.

## 사용 절차
1. 공통 카드·덱 보관함에 YDK를 등록한다.
2. 03 연결 진단에서 덱을 선택하고, 아래 04 선택 복구의 **원본 자료실 복구 후보 검사**를 누른다.
3. 카드별 원본, 동일/충돌 여부, 후보 이미지와 SHA-256 해시를 확인한다.
4. 가져올 **카드 정보**와 **일러스트**를 개별 체크한다. 기존 카드가 없는 경우 카드 정보도 함께 선택해야 이미지를 복구할 수 있다.
5. **선택 복구 승인**을 눌러 최종 확인 후 신규 기록만 복사한다. 연결 진단의 수치가 새로 반영된다.

## 데이터 보호 계약
- 원본 렌더러 프로젝트, 이미지 연구소 프로젝트, 기존 YDK, Lua, CDB, 승인·EDOPro 결과는 수정하지 않는다.
- 카드 ID가 같은 기존 카드의 이름·테마·효과가 다르거나 원본 자료실 간 정보가 충돌하면 해당 카드의 가져오기를 막고 원본을 나란히 보여준다.
- 기존 이미지와 후보 이미지가 다르면 실제 Blob SHA-256을 비교해 충돌로 표시하며 자동 대체하지 않는다.
- 복구는 기존 카드 ID가 없는 경우에만 신규 등록한다. 이미지도 IndexedDB `add` 사용으로 동일 ID가 동시 저장되면 트랜잭션이 중단된다.
- 검사 시점 공통 카드 원장이 다른 탭에서 바뀐 경우 쓰기를 차단한다.
- 이미지: PNG/JPEG/WebP, 개별 최대 7MiB, 배치 최대 96MiB. 초과·손상 데이터는 읽기 대상으로 제외한다.
- 카드 메타 저장 이후 이미지 저장이 실패할 수 있다. 이 경우 이미 저장한 신규 카드 건수를 알리고 다시 검사해 나머지를 선택하도록 한다. **전체 원자적 복구라고 주장하지 않는다.**

## 범위 제한
- 브라우저 보안상 **다른 주소의 GitHub Pages 저장공간이나 사용자 PC의 EDOPro 자료실을 직접 검색할 수 없다.**
- 이미지 연구소는 카드 메타정보만 조회한다. 이미지 후보는 통합 카드 렌더러에 명시적으로 저장된 data URI만 지원한다.
- 기존 충돌을 해소하거나 메타 효과를 자동 승인하지 않는다. 우회 덮어쓰기는 제공하지 않는다.
- 데이터 원본은 사용자의 현재 브라우저에 있어야 한다. 독립 사이트 자료는 기존 JSON/CSV/YDK/ZIP 이전 절차를 이용한다.

## 검증
- 단위: YDK 순서 불변, 카드 동일·충돌·소스 간 충돌, 이미지 SHA 일치/차이, 원본 불변성.
- 통합 Chromium: 실제 렌더러 IndexedDB 및 이미지 연구소 저장자료로 복구 후보 확인, 카드·이미지 각각 체크 후 승인, 기존 카드와 원본 렌더러 보존, 취소 시 공통 보관함 불변.
- 기존 V2.8 진단·V2.7 미디어 및 통합 ZIP 테스트를 회귀 실행한다.
