# YGO STUDIO V2.4 — 공통 스타일 · 로컬 렌더러 자산 이관

## 실측·코드 분석 결론

- 로컬 카드메이커 `http://127.0.0.1:5173`과 통합 웹 `https://bduidohd937-beep.github.io/ygocardganri/`는 **브라우저 Origin이 다릅니다.**
- 두 프로그램 모두 `duelmind-card-studio` IndexedDB의 `projects/current`에 프로젝트 JSON과 그림 데이터 URL을 저장합니다. 같은 DB 이름이어도 Origin이 다르면 **별도 DB**로 취급됩니다.
- 프레임·속성·폰트 리소스는 **별도 IndexedDB** `duelmind-card-studio-assets`의 `packs/current`에 저장합니다. 원본 ZIP에서 분류하여 `frame:...`, `font:name` 등으로 분리하고 Base64로 저장합니다.
- 통합본의 기본 카드 `이름 없는 카드`는 미등록 카드의 초기 상태이며 로컬의 `A7－00 이클립스`와 다릅니다. 빈 카드·다른 프레임은 UI 렌더링 엔진 회귀의 근거가 아닙니다.
- 로컬 화면에 표시되는 `kooriookami-assets-v3.zip · 54종 자동 적용`과 같은 자산팩은 **현재 브라우저에 로컬로 저장한 파일**이므로 다른 URL의 앱에 자동 전달되지 않습니다. 또한 올바른 마스크·폰트가 포함되어야 미리보기 모양이 일치합니다.
- GitHub Pages가 개인 PC의 localhost IndexedDB나 로컬 디스크 파일에 접근하여 자동 추출하는 일은 브라우저 보안 정책상 지원하지 않습니다.

## V2.4 실제 구현

1. **공통 디자인 토큰** `src/studioTheme.ts`: 스튜디오의 배경·패널·구분선·버튼·메뉴 활성 색상 기준을 카드 렌더러·이미지 연구소·DESIGN LAB·PSH에 적용.
2. 카드 렌더러와 이미지 연구소는 기존 네이티브 Shadow DOM의 **UI 크롬에만** 스타일을 덮어쓰며, 사용자가 만든 실제 카드 프레임 PNG·일러스트와 렌더링 알고리즘을 변경하지 않습니다.
3. DESIGN LAB·PSH는 현재 **동일 도메인의 전체 화면 iframe**에 기존 기능을 유지한 채 CSS만 주입합니다. iframe을 제거하는 네이티브 이식은 후속 범위입니다. 스타일 주입이 실패하면 원래 화면을 그대로 보여줍니다.
4. 카드 렌더러 전체 화면 우상단의 **로컬 자료 옮기기**에서 원본 렌더러의 JSON/ZIP 가져오기 입력을 직접 사용하도록 연결. 새 parser나 덮어쓰기 루틴을 만들지 않습니다.
5. 파일을 선택하면 사용자 확인창을 띄웁니다. 카드 JSON은 기존 병합 규칙(같은 ID의 기존 아트 보존), 프레임 ZIP은 기존 자산팩 교체 규칙을 따릅니다.
6. 실제 카드 화면과 원본 리소스 건수는 사용자가 최종 확인하도록 남깁니다. 이 안내가 성공이라고 주장하지 않습니다.

## 자료 이전 방법

1. 로컬 `127.0.0.1:5173`에서 **JSON 저장** → `프로젝트.json` 받기.
2. 로컬에서 카드 프레임을 만들 때 사용한 **원본 ZIP**을 찾기. 화면에 보이는 자산팩 이름과 ZIP 파일명을 비교.
3. YGO STUDIO → 카드 렌더러 → **로컬 자료 옮기기** → JSON 선택 → ZIP 선택.
4. 오른쪽 카드 목록에서 ID·카드명·일러스트가 맞는지, 왼쪽 아래 에셋팩 상태에 **원래 ZIP 이름과 54종**이 적용됐는지 확인.
5. 예: `A7－00 이클립스`를 선택해 엑시즈 프레임·어둠 속성·레벨/랭크·폰트·크롭 미리보기가 로컬과 같은지 확인.
6. 동일 ID가 이미 저장된 카드에 대해 무조건 덮어쓰기하지 않으므로, 일치하지 않는 경우 기존 JSON을 내보내 안전 백업 후 카드 ID 및 편집 내용을 개별 대조.
7. PC에 JSON·ZIP을 보존하고, 별도로 통합 사이트에서 새로운 JSON 백업을 받아 복구 가능성을 확인.

## 안전 한계와 차기 패치

- 이 패치는 스타일의 **일관성**과 수동 자산 이관을 제공하며 실제 모든 도구의 저장 엔진이 하나로 합쳐진 상태는 아닙니다.
- DESIGN LAB과 PSH의 iframe 제거는 기능별 이벤트·모듈 의존성·Origin 저장소 검수를 포함하므로 별도 개발 단계로 나누어 진행합니다.
- 이후 공통 카드 ID·이미지·덱 자료를 장기 저장소에 연결하고, 버전 및 원본 검증 후 사이트 정리.
- 라이선스가 확인되지 않은 외부 에셋 ZIP은 GitHub 소스 저장소나 공용 웹 자원에 자동 배포하지 않습니다. 사용자가 자신의 작업실에 직접 적용하는 방식만 사용합니다.
