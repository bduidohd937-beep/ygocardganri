# P6.1 — PSH AI ARENA·로컬 EDOPro 결과 수집 연동 계약

## 기준선과 선행 검수 (2026-11-12)
- YGO CARD STUDIO `main`의 P6.0 PR #25가 `a788e38`에 병합됨. CI에서 단위 108/108, Chrome 13/13 통과.
- 연결 대상으로 알려진 PSH AI ARENA V2.4 웹 경기장은 `AI_ARENA_WEB.cmd`, `127.0.0.1:8765`, 세션·로그·리플레이·CSV/JSON/ZIP 수동 내보내기 기능을 갖춘 **로컬** 프로그램이다. 이는 이전 사용자 보고를 바탕으로 한 설명이며 이번 GitHub 소스 검증과 다르다.
- GitHub의 `bduidohd937-beep/PSH-AI-ARENA` 저장소는 **비어 있다**. V2.4 실제 내보내기 JSON 필드, ZIP 구조, 소스 코드, 출력 경로는 현재 확인되지 않았다.
- V2.4/V2.4.1 경기장 교착 및 완료 0/2 보고를 고려하여, 로컬 실제 엔진 결과를 추정으로 보충하거나 교착 세션을 '실전 완료'로 변경하지 않는다.

## 구현 게이트
1. **소스 증거**: 실제 `AI_ARENA_WEB.cmd` 프로젝트와 최종 내보내기 예시(성공/실패/교착/중지)를 확보한다. 기존 로컬 프로그램이 파일을 생성한다고 가정하지 않는다.
2. **형식 정의**: 내보내기 JSON/CSV/ZIP의 원문 필드명과 버전·해시를 기록한 뒤 스키마별 읽기 전용 어댑터를 설계한다.
3. **검증용 샘플**: 동일 덱·5장/6장·완료/미완료·리플레이 유무·중복 세션·손상된 파일을 포함한 회귀 픽스처가 있어야 한다.
4. **검증된 증거만 연결**: 샘플에서 증명되지 않은 EDOPro 엔진 실행·리플레이 내부 해석·'자동 전개 성공' 표시를 금지한다.
5. **검증 후 배포**: 기존 P5/P6 회귀 테스트, 프로덕션 빌드·Chrome 테스트·원본 YDK/CDB/Lua 불변 확인을 통과한 변경만 병합한다.

## 수집 레코드의 최소 요구 필드
- `sourceSystem`, `sourceVersion`, `importedAt`, `sessionId`, `duelId`, `finishedAt`(존재하면)
- 완료 여부와 결과 원본 코드, 플레이어 A/B 또는 선후공, 목표 경기 수 및 실제 완료 경기 수
- 분석안 연결에 필요한 덱 식별자 / YDK 구성 지문 (일치하지 않으면 통계에서 제외)
- 초기 패 카드 ID 목록과 추출 방식 **실제로 기록된 경우에만** P6 패 통계로 연결
- 원본 로그·리플레이의 파일 존재 여부와 해시 / 검증 실패 사유
- 원본 출처 등급: `사용자 수동 입력`, `외부 내보내기 파일`, `엔진 로그 대조됨`을 구분하며 '자동 수집=엔진 검증'으로 간주하지 않는다.

필드가 불명확하거나 초기 패가 없는 세션은 **세션 결과만** 기록한다. 초기 패 확률 비교에 억지로 포함하지 않는다. 교착/취소/타임아웃은 성공·실패 경기에서 별도 보류로 기록한다.

## 안전 원칙
- GitHub Pages 정적 웹앱은 사용자의 로컬 디렉터리를 임의 검색하거나 EDOPro를 직접 실행하지 않는다.
- 초기 단계는 **사용자가 직접 선택한 내보내기 파일**에 한해 검증·읽기 전용 가져오기를 지원한다. 백그라운드 자동 감시나 업로드 없는 로컬 자동 수집 기능을 주장하지 않는다.
- 추후 별도 로컬 연결기가 필요하면 사용자의 명시적 실행 및 허용 범위, 최소 권한, 루프백 제한, Origin 검증, 인증·중단 기능을 먼저 검토한다. 임의 명령 실행·경로 탐색·원본 파일 수정은 금지한다.
- P6.0 기록·리플레이 Blob, P5 연구안, 파일 센터 YDK/CDB/Lua/이미지와 승인 효과는 서로 다른 저장소에 유지한다.
- 데이터 손상이 발생하면 묵시적으로 덮어쓰지 않고 보류·에러로 노출한다.

## 이번 패치와의 구분
**P6.0.1**은 기존 테스트 기록 JSON의 안전한 병합 복원만 구현했다. **P6.1 실제 PSH AI ARENA 파일 자동 변환·연동은 미구현**이며 출력 스키마 확보 뒤 착수한다. `108/108`과 `13/13`은 P6.0 기준 확인된 CI 수치이지 P6.1 실전 엔진 시험 결과가 아니다.

## P6.1 1차 수집함 (Alpha 0.6.2)
- 사용자가 선택한 JSON/CSV/ZIP 파일을 읽기 전용으로 분석하며 별도 IndexedDB `ygo_card_studio_arena_intake`에 원본 Blob과 SHA256/분석안 ID/리비전/지문을 저장한다.
- JSON 객체의 키·배열 모양, CSV 열 이름/행 수, ZIP 디렉터리의 파일명만 표시한다. 행 수·배열 길이를 **경기 수**로 오인하지 않는다.
- 동일 분석안 리비전·덱 지문·파일 SHA256은 중복 저장하지 않고, 다른 버전 자료는 현재 덱 결과에 포함하지 않는다.
- ZIP 파일은 내부 파일을 전혀 압축 해제하지 않으며, 최대 16MiB/200개 ZIP 엔트리/수집함 전체 200개 제한을 적용한다.
- 원본 파일 다운로드 시 SHA256 및 파일 크기를 다시 확인한다. 외부 로컬 원본, P5 연구안, P6 메타데이터/리플레이 저장소에 어떠한 수정도 하지 않는다.
- [검증 불가] PSH AI ARENA V2.4 공식 출력 스키마가 확보되지 않았으므로, 경기별 승패 추출·엔진 실행 증명·초동패 검출·타임아웃 판정·세션 자동 동기화는 수행하지 않는다.
- 검증 픽스처는 실제 EDOPro 경기 자료가 아닌 형식/보호용 인공 JSON/CSV/ZIP이다.

## P6.1 2차 — 세션 필드 수동 해석 (Alpha 0.6.3)
- 1차 수집함의 JSON·CSV 원본을 다운로드 전에 SHA256으로 검증하고, 파일의 배열·열 이름 중 사용자가 선택한 데이터셋만 검토한다.
- 세션 ID 필드·결과 코드 필드를 **명시적으로 사용자가 선택**하고, 각 원본 코드 값을 승리/패배/무승부/교착·중단/미확인으로 수동 분류한다. 자동 필드 추정·임의 결과 코드 해석은 금지한다.
- 동일한 세션 ID가 한 파일에서 2회 이상 확인되면 해당 ID의 **모든 행**을 승패·교착 집계에서 제외한다. 세션 ID가 없거나 길이 제한을 초과하는 행도 제외한다.
- 결과 코드가 선택되지 않았거나 매핑이 없다면 **미분류**로 세고 어떤 성공·실패 수치도 만들어내지 않는다.
- 분석 설정은 `ygo_card_studio_arena_review` 별도 IndexedDB에 저장한다. 소스 파일 SHA256·덱 연구안 ID/리비전/지문·낙관적 잠금 리비전을 포함해 무의식적인 덮어쓰기를 막는다.
- 메타데이터 검수 보고서에는 분류표와 원본 SHA256 및 집계만 포함한다. 원본 파일·EDOPro 리플레이 바이너리는 포함하지 않는다.
- JSON의 최상위 배열 또는 객체의 1단계 배열, CSV 헤더/행만 분석한다. JSON/CSV 10,000행·64필드·원본 상태 코드 30종·CSV 셀 4,096자 제한을 둔다.
- ZIP 내부 파일은 자동 압축 해제하지 않으며 세션 해석 대상에서 제외한다.
- 표시 집계는 **외부 파일에 대한 사용자 지정 분류**일 뿐, 엔진 실행·경기 완료·무작위 셔플·승률·전개 성공률을 검증한 것이 아니다. 기존 P5/P6 통계는 변경하지 않는다.
- 회귀 테스트는 인공 샘플만 사용하므로 실제 PSH AI ARENA V2.4 스키마를 입증하지 못한다. 실제 출력 샘플이 확보되면 정식 어댑터와 중단/교착 세션 검증 단계를 별도로 추가한다.
