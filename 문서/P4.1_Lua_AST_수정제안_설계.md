# P4.1 — Lua AST 정밀 검수 및 승인형 수정안

## 확정 구현 범위
- 기존 P4 문자열/파일 연결 검수는 유지
- `luaparse` 0.3.x로 Lua 5.3 AST 문법을 분석한다. 파서는 **검토용 도구**이며 EDOPro Lua 인터프리터를 대체하지 않는다.
- 효과의 `initial_effect` 함수 선언, 카드 ID 네임스페이스, `SetCondition/SetCost/SetTarget/SetOperation` 콜백, `Effect.CreateEffect`와 `RegisterEffect` 사용을 탐색한다.
- 카드명 기준 1턴 제한을 설명하는 원문에서 `SetCountLimit(1)`이 발견되면 **검토 제안**으로만 표시한다. `SetCountLimit(1,id)`, OATH, 효과별 코드 공유 등은 실제 재정과 함께 사람이 결정한다.
- `c<ID>.initial_effect`처럼 ID가 일치하지 않는 위치의 수정안을 제시할 수 있으나, 동일 파일의 다른 참조까지 자동 수정하지 않는다.
- 변경안은 원본 해시, 길이 및 정확한 바이트 해시·문자 범위를 확인한 다음 한 구간만 대체한다.
- 수정 전후를 비교하고 근거를 입력한 사람의 승인 이벤트가 기록된 후 **별도 검토안 파일**을 내려받을 수 있다.
- 업로드 Lua·CDB, 승인된 효과 원문, CDB 스키마, EDOPro 검증 상태는 자동 변경하지 않는다.
- Lua 원본은 128KiB 초과 시 정밀 분석·수정 제안 대상에서 제외한다. P4처럼 최대 200장, 각 카드 최대 3개 스크립트만 분석한다.
- AST 분석은 Worker 내부에서만 수행하며 초기 메인화면에 Lua 파서를 직접 로딩하지 않는다.

## 판정 수준
| 검출 | 표시 | 자동 확정 금지 |
|---|---|---|
| Lua 5.3 AST 파싱 실패 | AST_PARSE_REVIEW / 정적 의심 | 엔진 문법 오류라고 단정하지 않음 |
| 초기화 함수 네임스페이스 불일치 | AST_NAMESPACE_MISMATCH / 주의 | 파일 내부의 모든 참조 자동 교체 금지 |
| 카드명 공유 제한의 SetCountLimit(1) | AST_COUNT_LIMIT_CANDIDATE / 검토 | OATH·카드명 공유·발동/사용 차이를 판단 전 자동 반영 금지 |
| 미해결 콜백 함수 | AST_CALLBACK_UNRESOLVED / 검토 | 외부 헬퍼/동적 할당 여부 추가 확인 |
| 효과 생성 후 등록 코드 미발견 | AST_EFFECT_REGISTRATION_REVIEW / 검토 | 별도 소환/등록 헬퍼 가능성 검토 |

## 필수 검증
1. 정확한 `c<ID>` 수정안 생성 후 원본 SHA256가 일치할 때만 미리보기.
2. 정밀 검수는 기존 P4 보고서와 병합하되 사용자 승인된 상태를 덮어쓰지 않는다.
3. 새로고침 후 사용자의 승인 이력 유지. 원본 Lua 내용·승인 효과 원문 불변.
4. EDOPro 실제 카드 구동 시험을 수행한 것이 아니므로 정상 동작/규칙 적합 판정 불가.
