# P5 — 덱 연구실 설계 및 계산 기준

## 구현 목표
- 《녹투르나》 외 코스모코드·바티스 등 사용자가 만든 **모든 테마**의 가져온 YDK를 분석한다.
- 업로드한 원본 YDK는 브라우저 파일 센터의 그대로 보존한다.
- 원본과 별개로 덱 연구안을 생성해 메인 덱 매수, 카드별 역할, 전개 메모를 편집한다.
- 연구안은 P5 전용 IndexedDB(`ygo_card_studio_deck_lab`)에 저장한다. 저장 시 리비전을 확인하여 서로 다른 탭의 덮어쓰기를 방지한다.
- 연구안의 별도 JSON 백업·복원과 YDK 출력 기능을 제공한다. **CDB/Lua/이미지/YDK 원본 바이너리는 JSON 연구안 백업에 포함되지 않는다.**
- 40장 고정 로직을 두지 않는다. 메인 40~60장, 엑스트라/사이드 0~15장 상태를 표시하되, 이미 가져온 비정상 구성은 분석용으로 읽고 규격 경고를 제공한다.

## 수학적 모델

확률은 무작위로 잘 섞인 **메인 덱**에서 동일 확률로 초기 패 h장(5 또는 6)을 비복원 추출하는 경우로 한정한다.

- 초동: 사용자가 **초동** 역할을 지정한 카드가 최소 1장 들어올 확률
- 전개: 초동과 **전개보조** 역할이 각각 1장 이상 동시에 존재할 확률
- 말림 1: 초동 역할이 0장이고 **말림** 역할이 최소 1장 존재할 확률
- 말림 2: **말림** 역할이 최소 2장 존재할 확률

동일한 카드에 여러 역할 태그를 지정할 수 있으며, 겹치는 집합은 포함·배제를 사용해 정확하게 계산한다.

N = 메인 덱 수, K = 역할별 장수, h = 패 장수.

- P(역할 K장 중 최소 1장) = 1 − C(N−K,h)/C(N,h)
- P(A≥1 ∧ B≥1) = 1 − C(N−|A|,h)/C(N,h) − C(N−|B|,h)/C(N,h) + C(N−|A∪B|,h)/C(N,h)
- P(A=0 ∧ B≥1) = C(N−|A|,h)/C(N,h) − C(N−|A∪B|,h)/C(N,h)
- P(K≥2) = 1 − C(N−K,h)/C(N,h) − K·C(N−K,h−1)/C(N,h)

조합 수를 직접 정수로 전개하는 대신 60장 이하의 연속 곱 비율을 사용해 수치가 범위를 넘지 않도록 한다. 미분류 역할은 **확률 0%**가 아니라 **태그 미설정**으로 표시한다.

## 카드 목록·매수 편집
- 기존 원본 YDK의 카드 ID를 목록에 표시하고, CDB로 확인된 카드명만 연결한다.
- 역할은 초동 / 전개보조 / 말림 / 패트랩으로 수동 태깅한다. 자동 역할 분류를 하지 않는다.
- 연구안에서 카드 ID별 메인 덱 0~3장을 편집하고 직접 ID를 추가할 수 있다.
- 메인+엑스트라+사이드 같은 ID 3장 기본 상한과 60장 메인 상한을 편집 단계에서 확인한다.
- **금지·제한·준제한 카드 목록은 아직 연동하지 않았다.** 덱 적법성 자동 판정 금지.
- 40장 미만/60장 초과, 엑스트라·사이드 각 15장 초과, 동일 ID 3장 초과는 검토 경고로 구분한다.
- 원본 YDK와 현재 연구안의 패 확률을 동일한 역할 태그 기준으로 비교한다. 제거된 카드의 역할 태그는 원본 비교를 위해 남겨둔다.
- 메인 덱의 5장 또는 6장 패 분포만 계산한다. 유희왕의 실제 1턴 전개, 서치, 묘지 자원, 선공 방해, 소환 제한, 덱 혼합 연계, 승률은 반영하지 않는다.

## 데이터 보호와 복원
- P5 저장소는 P1 설계/승인, P2 파일 원본, P3 작업 문서, P4 분석·판정과 별개다.
- 다중 탭 충돌은 리비전 일치 조건의 IndexedDB readwrite 트랜잭션으로 보호한다.
- 백업 복원은 **P5 연구안 전체만** 교체하고, 다른 저장소는 건드리지 않는다. 복원 전 명시 확인.
- 원본은 계속 독립적으로 남고, 연구안만 삭제 가능하다.

## 검증 범위
- 단위 테스트로 하이퍼지오메트릭 값과 겹치는 역할, 정확히 2장 말림, 채용 매수 및 YDK 왕복을 검증.
- Chrome 자동 테스트로 40장 YDK 업로드 → 연구안 생성·수정·확률 표시 → 저장·다운로드 → 재접속·원본 보존 확인.
- 기능 검증과 실제 메타 덱 성능은 분리한다.
