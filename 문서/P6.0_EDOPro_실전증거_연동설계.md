# P6.0 — EDOPro 실전 테스트 증거 연동

## 범위와 근거
이 프로젝트는 GitHub Pages에서 실행되는 정적 React 웹앱이다. 브라우저에서 EDOPro 실행 파일을 자동 실행·조작하지 못하며, 리플레이를 해석할 엔진도 없다. 따라서 P6.0은 **실제 EDOPro 테스트 결과를 수집하고 보관하는 단계**다. 전개 성공은 사용자의 수동 판정이다.

- 공식 Project Ignis FAQ: https://projectignis.github.io/faq.html
  - EDOPro의 최신 리플레이는 .yrpX, 구형 형식은 .yrp.
  - 최신 리플레이 파일이 필요한 경우 _LastReplay.yrpX를 확인할 수 있다.
  - EDOPro 덱 편집기의 Test Hand나 LAN 자기 대전/AI 대전으로 카드 오류 재현 가능.
- 공식 문서: https://github.com/ProjectIgnis/Distribution/blob/master/README.md

## 사용 절차
1. 파일 센터에서 YDK·CDB·Lua 원본을 별도로 가져온다. CDB와 Lua의 기능 검수는 기존 P4에서 수행한다.
2. 덱 연구실에서 YDK의 연구안을 만들어 저장하고 P5.2의 A/A+B 및 금지 패·추가 자원 조건을 설정한다.
3. **분석안 YDK 출력** 후 사용자의 EDOPro 환경에 로드한다. 이 웹앱은 EDOPro를 실행하지 않는다.
4. 실제 EDOPro에서 초기 패 5장/6장을 관찰한다.
5. 첫 패의 **카드 ID**, 무작위 셔플 / 의도적 Test Hand / 미확인 중 실제 방식, 전개 성공·실패·보류 판정, 원인 메모를 입력한다.
6. 첨부할 수 있다면 .yrpX(.yrp) 리플레이 원본을 업로드한다. 최대 16MiB. SHA256을 계산하여 파일과 함께 IndexedDB에 보관한다.
7. 현재 덱 구성·루트 정의·연구안 리비전과 연결한 기록을 저장한다. 사용자 보고라는 표시를 유지한다.
8. 무작위 셔플로 표시한 완료 기록만 모아 수동 보고 성공 비율을 계산하고 P5.2 이론상 패 구성 확률과 나란히 확인한다.

## 엄격한 신뢰 수준
- **이론상 초동 패 조건 충족률**: P5.2 수학적 모델의 모든 가능한 비복원 초기 패 조합 중 사용자 지정 조건이 충족되는 비율.
- **실측 성공(사용자 기록)**: 사용자가 EDOPro에서 테스트한 것으로 *보고*한 성공 횟수 / 완료 횟수. 별도 엔진 텔레메트리로 검증되지 않았다.
- **리플레이 첨부(미해석)**: 파일명, 원본, 크기, SHA256만 기록한다. 이름이나 해시만으로 듀얼 내용·정상 작동을 인증할 수 없다.
- **이론/판정 불일치**: 카드 ID의 초기 패 조건과 사용자 판정 사이의 차이. 자동 룰 위반·스크립트 버그 판정은 아니다.
- 무작위 셔플은 **사용자 표시**이며 웹앱이 관찰/증명한 무작위 과정이 아니다. Test Hand를 일부러 고정한 경우 표본 성공률에 포함하지 않는다.
- 여러 연구안·새 리비전·서로 다른 덱 구성·루트 정의·5/6장 패는 통계적으로 섞지 않는다.
- 어떤 수치도 검증된 승률, 상대 견제에 대한 전개 성공률, 룰 적합성을 보증하지 않는다.

## 데이터와 개인정보 보호
- P6 증거는 독립 브라우저 IndexedDB("ygo_card_studio_engine_evidence")의 기록/리플레이 별도 저장소.
- 저장 트랜잭션에서 기록 메타데이터와 첨부 리플레이를 함께 저장한다.
- 리플레이 다운로드 시 SHA256을 확인하며 변경/손상된 원본은 전달하지 않는다.
- 저장된 YDK, Lua, CDB, 이미지, P5 분석안, 카드 승인 효과/상태는 P6에서 변경하지 않는다.
- JSON 백업은 기록 메타데이터만 포함하고 리플레이 원본 바이너리는 포함하지 않는다. P6.0.1에서 기존 백업을 기록 ID 기준 **원자적으로 병합 복원**할 수 있지만, 리플레이 파일 자체는 복원하지 않는다. 같은 ID에 다른 기록이 있으면 전체 병합을 취소한다.
- 브라우저의 사이트 데이터 삭제·브라우저 변경·프라이빗 창·스토리지 정리에 따라 보관된 근거가 사라질 수 있다. 중요한 리플레이는 외부 폴더에도 백업한다.

## 구현 검사
- Vitest: 실제 덱 매수보다 많은 중복 카드 손패 차단, P5.2의 금지 그룹·별도 자원·A+B 실물 분리, 무작위/의도 패/미확인 결과 필터, 다른 덱 버전/패 크기 혼합 방지, JSON 메타데이터 형식.
- Playwright Chrome: 40장 YDK 업로드 → 분석안 저장 → 실제 테스트 기록 형식으로 결과·리플레이 첨부 → SHA256 보관 → 재접속 → 브라우저 내 원본 바이트 재다운로드 → 사용자 보고 통계 확인 → 원본 YDK 40장 유지.
- 추가로 TypeScript·프로덕션 빌드·번들 크기 예산·정식 GitHub Pages CI 검증.

## P6.0.1 추가 검증
- JSON 백업을 가져와도 기존 기록과 리플레이 Blob을 삭제·변경하지 않는다.
- 중복 ID의 동일 기록은 건너뛰며 충돌 시 변경 없이 취소한다.
- JSON만 복원한 리플레이 메타데이터를 실제 리플레이 파일 검증으로 오인하지 않는다.
