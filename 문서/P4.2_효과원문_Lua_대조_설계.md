# P4.2 — 효과 원문 ↔ Lua 구조 비교 설계

## 목적
CDB에서 추출한 효과 텍스트(또는 별도 승인된 효과 원문)와 카드별 Lua 5.3 AST 구조를 **근거와 함께** 비교한다. 목적은 사람이 확인할 작업을 빠르게 찾는 것이지, OCG 규칙의 적합성 또는 EDOPro 실행 성공을 증명하는 게 아니다.

## 비교 기준과 출처
- 승인 효과 원문이 있으면 이를 우선 사용하며 `승인 효과 원문 (CDB와 다를 수 있음)`으로 출처를 표시한다. 승인 원문이 없다면 같은 카드 ID의 CDB 원문을 사용한다.
- 승인 원문 없이 CDB 파일 간 효과 문구가 충돌하면 기준을 **확정하지 않는다**. 기존 P4의 CDB 충돌 경고를 유지하며 P4.2는 전 단계를 `판별 불가`로 기록한다.
- 각 Lua 파일별 독립 비교 결과를 표시한다. 같은 카드에 Lua 원본이 여러 개면 누락을 임의로 판단하지 않는다.
- 각 결과는 `(테마 ID, 카드 ID, Lua 파일 ID, 텍스트 지문)`으로 구별한다. 보고서는 기존 감사 JSON에 별도 `comparisons` 자료로 추가한다.

## 4단계와 판정
| 단계 | 명시적 원문 단서 | 확인할 Lua 구조 | 주의 |
|---|---|---|---|
| 발동 조건 | ~했을/되었을 경우에 발동 | `SetCondition` | `SetType`/`SetCode` 트리거로 조건 표현 가능 |
| 코스트 | 패에서 버리고 발동, LP 지불하고 발동 등 | `SetCost` | 효과 처리의 버리기/제외와 혼동 주의 |
| 대상 | ~을 대상으로 하고 발동 | `SetTarget` 및 `EFFECT_FLAG_CARD_TARGET` | `SetTarget`만 있는 경우 검토 후보 |
| 효과 처리 | 특수 소환·파괴·제외·패로 보내기·묘지로 보내기 | `SetOperation`과 `Duel.SpecialSummon/Destroy/Remove/SendtoHand/SendtoGrave` | 다른 Lua 함수·절차·헬퍼로 처리 가능 |

판정은 `구조 발견`, `검토 필요`, `판별 불가`, `문구 없음` 네 가지다. `구조 발견`은 코드 내부 호출이 **존재함**을 뜻할 뿐 효과 원문과 실행 동작이 일치한다는 뜻이 아니다. `문구 없음`은 현재 인식 가능한 한국어 패턴을 찾지 못한 경우이며, 해당 기능이 없다는 의미가 아니다.

## 판별 불가로 유지할 사항
- 한 장의 카드에 ①②③ 등 번호가 여러 개 있거나, 스크립트 원본이 여러 개 있는 경우
- Lua 객체가 여러 개 등록되거나 다른 절차/보조 헬퍼가 등록을 수행하는 경우
- AST 파싱 불가, Lua 원본 접근 불가 또는 본문 일부만 읽은 경우
- 텍스트와 직접적인 코드 호출이 연결되는지 증명할 수 없는 경우

이 경우 누락·오류를 단정하지 않는다. 위젯은 코드를 **카드 전체 범위**에서 비교하므로, 개별 번호 효과 ①과 e1이 반드시 대응한다는 주장도 하지 않는다.

## 보존·성능·검수 정책
1. P4.2는 P4·P4.1의 분석 결과를 유지하고, 비교 결과와 의심 항목만 추가한다.
2. 분석은 기존 Web Worker 내부에서만 실행한다. P4 상한(최대 카드 200종, Lua 3개/카드, 128KiB 미만)을 유지한다.
3. CDB, Lua, 이미지, YDK, 승인 원문, Lua 수정안, 개별 검수 상태를 변경하지 않는다.
4. `ALIGN_*_REVIEW`는 `정적 의심` 및 `검토` 등급으로만 추가되며, 자동 OCG/EDOPro 합격 상태는 생성하지 않는다.
5. 검사 단위/브라우저 회귀 테스트 통과와 실제 듀얼 엔진 동작 검증을 엄격히 구분한다.

## 후속 개발
P4.3에서 효과별 `SetDescription`/`aux.Stringid` 대응과 콜백 함수 내부의 데이터 흐름을 더 정밀하게 연결하는 방향을 검토한다. 최종 OCG 판단과 실전 검증은 P6 EDOPro 실행 결과를 통해 별도로 평가한다.
