# P4 정적 오류 분석 V0.4

## 목표

업로드된 CDB 효과 텍스트와 승인 원문·Lua 원본·카드 파일 인덱스를 비교해 **자료로 확인된 사실**과 **문자열/코드 패턴으로 의심되는 사항**을 분리해 제시한다. 분석 결과 자체가 OCG/EDOPro 검증 완료를 의미하지 않는다.

## 첫 구현 규칙

| ID | 검출 | 분류 |
|---|---|---|
| CDB_CONFLICT | 동일 테마 동일 카드 ID에 서로 다른 CDB 원문/카드명 | 자료 확인 |
| LUA_VARIANTS | 동일 카드 ID에 해시가 다른 Lua 파일 | 자료 확인 |
| APPROVED_CDB_DIFF | 승인 효과 원문과 추출 CDB 텍스트 차이 | 자료 확인 |
| MISSING_CDB / MISSING_LUA | 현재 브라우저 보관소에 대응 원본 미등록 | 자료 확인(검토) |
| LUA_ID_MISMATCH | c<ID>.lua와 `function c<other>.initial_effect` ID 상충 | 자료 확인 |
| LUA_INITIAL_EFFECT | 효과 본문이 있는데 Lua 내 `initial_effect` 정의 부재 | 자료 확인(실행 오류 확정 아님) |
| COUNT_LIMIT_REVIEW / COUNT_LIMIT_PER_COPY | 카드명 1턴 제한 표현과 `SetCountLimit` 호출 의심 | 정적 의심 |
| TARGET_FLAG_REVIEW | 대상 표현과 `EFFECT_FLAG_CARD_TARGET` 부재 | 정적 의심 |
| SUMMON_IMPLEMENTATION_REVIEW | 특수 소환 표현과 일반적인 소환 API 부재 | 정적 의심 |
| MISSING_LOCAL_CALLBACK | SetTarget/Cost/Condition/Operation의 `s.fn` 참조가 같은 파일에 없음 | 정적 의심 |
| LUA_TRUNCATED / LUA_SCAN_LIMIT | 스캔에 일부 내용/원본이 미포함 | 미검사 범위 표시 |

**정적 분석의 의미:** 파서가 없고 Lua 실행을 하지 않는다. 헬퍼·유틸리티 호출, 간접 효과 등록, 카드 종류별 특수 처리 등이 존재하므로 '없음'은 OCG 위반 확정이 아니다.

## 안전·성능

- 유효한 테마의 연결된 카드만 검사하며 승인 원문과 CDB/Lua 원본을 수정하지 않는다.
- 테마 검사 최대 200장/실행. 그 이상은 미검사 사실을 명시한다.
- 카드별 Lua 원본은 최초 3개, 파일당 최대 128KiB만 읽는다. 나머지는 **미검사**를 별도 표시한다.
- 병목이 되는 패턴 분석은 Web Worker에서, 파일 조회는 별도 비동기 작업에서 수행하고 중단할 수 있다.
- 발견 항목은 규칙 ID, 파일 출처, 인용된 근거, 심각도, 의심/자료 확인 구분, 재검토 방법을 포함한다.
- 동일 테마·카드ID·규칙·원본 SHA로 안정적인 발견 키를 생성하고 이 키로 수동 검토 이력을 별도 IndexedDB에 보관한다.
- 수동 '확인됨'/오탐 기록은 근거 메모를 요구하고 CDB 원문 승인, OCG 통과, Lua 테스트 상태를 변경하지 않는다.
- JSON 보고서 내보내기에는 검사 시각과 스캔 범위, 수동 조치 이력을 포함하나 업로드 원본 전체를 담지 않는다.
- 서로 다른 테마의 동일 카드 ID는 서로 다른 카드로 보관한다.

## 한계와 후속 과제

1. 정규식 검사는 Lua 문법/AST/실행/재정 판정이 아니다. P4.1에서 Lua 문법 파서 및 검증 가능한 추가 룰을 검토한다.
2. 'CDB 원문과 Lua 구현의 의미가 일치하는가'는 결정적으로 판단할 수 없다. 표현/함수 매핑은 수동 검토 후보만 제공한다.
3. 대량 배치의 전수 검사는 분할 실행과 재개 이력, 안전한 백그라운드 작업이 필요하다.
4. EDOPro 실제 기능 성공 여부는 P6 별도 격리된 테스트 러너에서 확인한다.
