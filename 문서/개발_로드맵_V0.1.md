# 개발 로드맵 V0.1 — YGO CARD STUDIO

- 기준일: 2026-11-11
- 저장소: https://github.com/bduidohd937-beep/ygocardganri
- 상태: 기획 확정 후보. 각 단계는 테스트 통과 후 완료로 갱신한다.
- 범위: **사용자가 만든 모든 유희왕 오리지널 테마**. 《종언성서 — 녹투르나》와 《무명성서》는 첫 번째 시범 데이터셋이지, 플랫폼의 구조적 한계가 아니다.

## 제품 정의

카드의 **기획서(의도)**, **승인된 원문(기준선)**, **CDB 데이터**, **Lua 스크립트**, **이미지**, **덱 구성**, **규칙 검토**, **실전 테스트**가 서로 다르거나 누락되면 즉시 찾아낼 수 있는 제작 워크벤치.

카드 전용 내부 UUID를 사용한다. EDOPro의 패스코드/카드 ID는 별도 필드이며, 패스코드 중복·다른 파일 사이의 불일치·미배정 상태를 추적한다. 외부 파일과 내부 엔터티의 연결은 사용자 확인 후 확정한다.

- [ ] 컴포넌트: 테마 사이드바, 검색, 데이터 테이블, 상세 편집기, 상태 배지, 타임라인, 변경 비교, 오류 패널

### P1. 데이터 코어와 초기 콘텐츠 이관

- [ ] 세계관과 카드 효과를 서로 참조하는 관계(고난→극복→지배, 사용 카드, 장면, 단계)
- [ ] 《종언성서 — 녹투르나》 5개 세계, 확정 레벨 4 아벨 5종, 진화 placeholder 10종과 공통 《기억을 잃은 자－아벨》 별도 등록
- [ ] 기존 승인된 5개 아벨 이름·세계별 소환 축 등만 확정. 미확인 효과·승인/구현 여부는 명시적 '미확인'
- [ ] 테마·카드 탐색, 검색/필터/정렬, 상세 변경, 감사 이력, JSON 내보내기/가져오기, 구버전 백업 호환

**완료 기준:** 카드 5종 각각 독립적으로 수정·복원 가능, 승인 전 제안이 원문을 덮어쓰지 않음, 백업→초기화→복원 왕복 테스트 성공.

### P2. CDB·Lua·이미지·YDK·ZIP 다중 업로드 / 인덱싱
- [ ] Drag & Drop 업로드 / 여러 파일 일괄 가져오기 / 포맷별 프리뷰
- [ ] CDB(SQLite) 파서: datas/texts·카드 ID·카드 타입·스탯·효과 문자열 등 수집. 읽기 우선, 원본 덮어쓰기 금지
- [ ] Lua 인덱서: 파일명 `c<id>.lua` 기준 연결, 파일 텍스트 및 구문·API 참조 구조 추출. 업로드 즉시 실행하지 않음
- [ ] 이미지(PNG/JPG/WebP): 이미지 메타/썸네일/ID 매칭, 승인된 최종본과 후보안 분리
- [ ] YDK 파서: 메인/엑스트라/사이드 섹션, 카드 ID·동일 카드 매수·미등록 카드 확인
- [ ] ZIP 수집: 경로 이동·중첩 압축·비정상 파일·크기 폭주 방어, 합리적 용량 제한
- [ ] 자동 연결을 제안하되, 중복 ID/상이한 카드명/누락 파일은 충돌 큐에서 사람이 판단
- [ ] 원본 파일 해시, 출처, 업로드일, 파서 버전, 파싱 오류, 덱·카드 연결 상태 보존
**완료 기준:** 테스트용 CDB+Lua+이미지+YDK 묶음 업로드 후 카드별 4종 파일 연결 현황을 표시하고, 충돌/누락/무효 파일을 구별해 리포트 출력.

### P3. 카드 설계 스튜디오 + 승인 워크플로
- [ ] 카드 사양 편집(카드명/레벨·랭크·링크/속성/종족/펜듈럼 스케일 등 포맷별 필드)
- [ ] 카드 효과 확정 원문과 미승인 제안 별도 버전/저장소; 1개 제안 선택→diff 검토→승인
- [ ] 아트 리비전/이미지 승인/설정 승인/OCG 검토/EDOPro 검증을 서로 독립된 상태로
- [ ] 승인자·시각·근거·변경 전후·테스트 링크를 보존하는 삭제되지 않는 감사 로그
- [ ] 되돌리기는 이전 상태를 **새 리비전**으로 생성하며 기존 승인 기록을 지우지 않음
- [ ] 명확한 필드 출처와 확정/제안/미확인 구분
**완료 기준:** 제안 반려·수정·승인·롤백 각 경로에서 기준선과 이력이 유실되지 않는 자동 테스트 통과.

- [ ] 1차 결정적 검사: CDB 필수 데이터, 레벨·랭크·링크 등 타입/비트마스크, 카드 ID/파일명, 문자열 누락, 상충 데이터

- [ ] OCG 표현 체크리스트: 발동 조건·코스트·대상·처리·1턴 제한·체인/타이밍·소환 절차·지속/유발 효과 등
- [ ] AI는 근거 있는 '검토 후보'와 추천 수정문·diff를 생성. 검증완료라는 결론을 임의로 부여하지 않음
- [ ] 항목별 심각도/근거/수정 제안/검토자 결정/재발 방지 테스트 기록
**완료 기준:** 알려진 오류 샘플을 검출, 정상 샘플에 대한 오탐 기록, 모든 AI 수정은 사람 승인 전 원본 불변.

### P5. 덱 연구실

- [ ] 덱의 카드 ID 누락/중복/분류/매수·메인/엑스트라/사이드 구성 검증

- [ ] 확률 계산은 정확한 조합식/시뮬레이션 가정 공개; 실제 카드 효과가 없는 한 전개 성공을 단정하지 않음

## 사용자 경험과 화면

1. **작업 대시보드:** 마지막 작업, 미승인 효과, 파일 누락, 우선 수정할 카드, 실패 테스트. 의미 없는 통계 장식 최소화.
2. **테마 도서관:** 모든 오리지널 테마 카드 갤러리·검색·상태 필터·컬렉션. 《무명성서》 등 세계관 상세.
3. **카드 상세 워크벤치:** 왼쪽 카드 이미지와 기본 스탯, 가운데 효과 원문과 diff, 오른쪽 출처·승인·검수·연결 파일·테스트 결과.
4. **파일 검수함:** 업로드 파일별 카드 ID 매칭/중복/누락/구문 오류 대조 테이블.
5. **덱 연구실:** 덱 레시피, 초기패 확률, 카드별 출현 빈도, 전개 로그, 실전 테스트.
6. **릴리스 센터:** 설치 패키지/버전/다운로드/호환성/회귀 테스트 기록.

디자인은 고서 기록보관소의 절제된 시각 언어 + 고밀도 엔지니어링 소프트웨어의 정확한 데이터 위계를 결합한다. 'AI가 만든 듯한' 남발된 그라데이션, 동일한 둥근 카드, 모호한 아이콘과 장식 그래프는 지양한다.

## 권장 아키텍처

- **프런트:** TypeScript + React + Vite, 화면/파일 처리 기능 분리, 반응형 디자인
- **로컬 파일 파서:** sql.js/WebAssembly를 이용한 CDB 읽기, Lua 텍스트/AST 정적 분석, YDK 텍스트 파서, 이미지 메타데이터. 대용량 파싱은 Worker 활용
- **검증:** Zod(입력 스키마), Vitest(로직), Playwright(브라우저), CI 빌드
- **초기 저장:** IndexedDB + 명시적인 JSON 및 원본파일 백업. 브라우저 데이터 삭제 시 유실 가능성을 고지
- **확장 저장:** 서버 DB(PostgreSQL 등) + 오브젝트 스토리지 + 인증/권한, 이후 GitHub PR/릴리스 연계
- **배포:** 초기 공개 프런트는 GitHub Pages 또는 별도 정적 호스팅 가능. 영구 공유/업로드/서버 분석은 별도 백엔드 필요
- **실제 시뮬레이터 실행:** 독립 테스트 러너/로컬 에이전트. 웹업로드와 엔진 실행 경계를 분명히 유지

## 데이터 구조(초안)

- `Project` / `Theme` / `World` / `LoreEvent` / `EvolutionStage`
- `Card`(내부 UUID, 외부 EDOPro ID는 미확인 가능) / `CardRevision` / `EffectProposal` / `ApprovalEvent`
- `Asset`(종류, sha256, 출처, URL/저장 위치, 상태) / `CardAssetLink`(해시와 매칭 근거)
- `Deck` / `DeckRevision` / `DeckEntry`
- `ValidationFinding`(rule_id, 심각도, 근거, 제안, 상태) / `TestRun`(엔진 버전, 로그, 재현, 판정)
- `AuditEvent`(actor, at, before/after, 이유, 관련 리비전)

원본 파일은 별도의 버전 불변 객체로 유지하고, 파서의 정규화 결과를 연결한다. 서로 다른 파일의 내용이 어긋날 때 '자동 정답'을 만들지 않는다.

## 고품질 게이트

- 기능은 **보이는 버튼이 아니라 테스트되는 동작**이어야 한다.
- 사용자 업로드 원본은 명시적 교체 승인 전 덮어쓰지 않는다.
- 확정, 설계 승인, OCG 검토, Lua 구문 통과, 실제 듀얼 검증을 합쳐 단일 '완성' 표시로 만들지 않는다.
- 각 검수 항목에 근거, 심각도, 검토 상태, 재현 방법을 첨부한다.
- 카드 ID 중복이나 깨진 CDB는 가져오기를 강행하지 않고 수동 해결 화면으로 보낸다.
- 입력 파일에서 받은 Lua를 무조건 실행하는 파이프라인은 만들지 않는다.
- 수정된 카드의 연결 덱·지원 카드·테스트 목록을 영향도 분석에 포함한다.
- CI: 타입 검사 + 정적 검사 + 핵심 파서 테스트 + 기능 단위 테스트 + UI 스모크 + 빌드.

## 우선순위 조정 기준

**가장 먼저 가치가 생기는 범위:** P0→P1→P2 순으로, 테마·카드 화면과 실제 사용자의 카드 파일을 안정적으로 연결한다. P3(승인) 이후에야 P4의 AI 수정 자동화를 적극 도입한다. P6 실전 검증을 선행했다고 거짓으로 표시하는 경우는 없어야 한다.

원래 존재하는 《무명성서》 HTML V2는 **데이터 백업을 통해 이관할 참고 구현**이며, 이 저장소에 아직 포함되어 있거나 배포되어 있다고 가정하지 않는다.
