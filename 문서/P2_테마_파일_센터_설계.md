# P2 — 멀티테마·파일 센터 설계 및 경계

## 목표

* 모든 커스텀 테마를 독립적으로 등록한다. 초기 테마로 《종언성서 — 녹투르나》 1종만 제공한다.
* 선택한 테마에 원본 CDB·Lua·이미지·YDK·ZIP 파일을 보관하고 카드 ID로 인덱싱한다.
* 승인된 카드 원문과 업로드에서 발견한 효과 텍스트는 **서로 다른 자료**이며, 업로드는 승인된 원문을 덮어쓰지 않는다.

## 저장·이관 정책

* 기존 《녹투르나》 카드·세계관·승인 자료: `ygo_card_studio` / `workspace` / `project_v1`. 변경하거나 초기화하지 않음.
* 신규 파일 메타·테마·읽기 전용 카드 ID 인덱스: `ygo_card_studio_file_vault` / `catalog`.
* 원본 파일 바이트: 같은 DB의 `originals` 스토어, 메타데이터와 동일한 트랜잭션으로 저장.
* 둘 모두 브라우저에만 저장되며 **JSON 카드 백업에는 바이너리 파일이 들어가지 않는다.** 반드시 업로드 원본을 다른 곳에 보관한다.
* 데이터의 수정/삭제/백업/복구 통합은 이후 단계에서 작업한다. 스키마 버전은 파일 카탈로그 1을 사용한다.

## 파서

| 포맷 | 인식 | 처리 | 승인 판정 |
| --- | --- | --- | --- |
| CDB | SQLite 헤더 / `datas`, `texts` | ID, 이름, 효과 텍스트 **읽기 전용 추출** | 미승인 / 별도 검토 |
| Lua | `c<ID>.lua` | ID 추출, `initial_effect` 함수 존재 여부 검사 | 실행·규칙 검증 미수행 |
| 이미지 | PNG/JPG/WebP 시그니처, 카드 ID 파일명 | 해시/크기/카드 ID 매칭 | 일러스트 승인 미수행 |
| YDK | `#main`, `#extra`, `!side` | 카드 ID 목록, 매수, 미등록 참조 | 덱 규칙 검증 미수행 |
| ZIP | JSZip 읽기, 경로/용량/비정상 압축률 제한 | 원본 ZIP 및 허용 확장자 내부 파일 보관 | 원본 보관만 수행 |

## 브라우저 성능·안전성

* 업로드/파싱은 모듈 Worker로 격리하고, 사용자 취소 시 `terminate()`로 중단.
* 파일 500개, 직접 파일 25MB, 내부 파일 12MB, 총 처리량 60MB 제한. ZIP 경로 이동/원격 경로/이상 비율 거부.
* 파일명, 해시, 경로, 저장 시각, 소속 테마 및 파싱 경고 표시. 동일 카드 ID/종류의 다른 파일이 있으면 충돌로 보고하되 자동 교체 금지.
* CDB의 `desc` 문자열은 임의 변환하지 않는다. 파일 구조는 버전/패키지에 따라 다를 수 있어 파서 실패를 오류로 보고.
* Lua는 Worker 내에서도 **실행하지 않는다**. `initial_effect` 존재만으로 구문·발동·동작 검증 완료를 주장하지 않는다.
* 확정 카드 ID가 없는 《무명성서》 초기 카드 5종에는 업로드 파일을 **이름으로 강제 연결하지 않는다**.

## P3 이전의 제한

* 새 테마의 카드 등록 및 승인 원문 편집은 기존 《녹투르나》 워크벤치와 통합되지 않았으며, 현재는 **파일 자료 인덱스만** 제공한다.
* ZIP 원본/개별 파일 및 카드 카탈로그에 대한 ZIP 전체 백업/교체/원격 동기화는 미구현이다.
* 웹 페이지는 EDOPro 실행이나 Lua 실행 권한을 갖지 않는다.

## 수용 테스트

- 정상 CDB/루아/YDK/이미지/ZIP, 손상 CDB, 위험 ZIP, 동일 ID 충돌, 다른 테마 격리, 사용자 취소 검증
- 저장 후 페이지 재진입해 원본 다운로드 가능 및 해시 동일 확인
- 기존 16개 카드 초기 데이터·승인 원문·기존 V1 로컬 백업 회귀 테스트 통과
- 타입 검사, Vitest, Playwright, 번들 용량 예산과 프로덕션 빌드 통과
