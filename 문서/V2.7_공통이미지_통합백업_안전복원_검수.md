# YGO STUDIO V2.7 — 공통 일러스트 연결 · 통합 백업/복원 검수

## 핵심 변경

1. **통합 백업:** ‘기존 사이트 데이터 이전’ 화면에 현재 GitHub Pages Origin에서 사용할 수 있는 9개 지정 데이터 저장소와 공통 이미지 보관함의 원본을 읽기 전용으로 묶는 ZIP 스냅샷을 추가했다. 카드 렌더러의 일러스트 Data URL, 프레임/폰트 리소스팩, DESIGN LAB 원본 파일 Blob, 카드·덱 메타, PSH 수동 관제 기록 등을 JSON + 원본 바이너리로 포장한다.
2. **검증:** ZIP 파일에 각 JSON 레코드와 Blob의 SHA-256, 크기, 저장소 식별자, 복원용 키가 포함된 `백업목록.json` 생성. 복원 전에 경로·형식·해시를 대조하며, 등록되지 않은 파일/중복 경로/손상 파일/허용되지 않은 저장 키를 거부한다.
3. **기존 기록 보호:** 사용자 확인 후 ‘없는 키만 추가(add)’를 기본 복원 방식으로 구현. 기존 앱에 저장된 같은 ID·키는 덮어쓰지 않는다. 복원 과정에서 변경됐던 작업실은 새로고침 후 실제 결과를 확인해야 한다.
4. **이미지 ID 연결:** 통합 카드 렌더러에 저장된 카드 일러스트 중 공통 카드·덱 보관함에 등록된 숫자 카드 ID와 일치하는 이미지만 사용자가 명시적으로 복사. `ygo-studio-shared-media-v1/images`에 ID 기반 Blob, MIME, SHA-256, 출처를 보관한다. 기존 이미지 ID가 있으면 변경하지 않으며, 미리보기/원본 이미지 다운로드 제공.
5. **이미지 인덱스 백업:** 별도 공통 이미지 Blob 저장소도 V2.7 ZIP에 포함. 빈 저장소와 기존 이미지·카드 프로젝트 데이터를 구분한다.

## 포함되는 데이터

| 저장소 | 백업 항목 | 보존 방식 |
|---|---|---|
| `ygo_card_studio/workspace` | 녹투르나 카드 원장 | JSON |
| `duelmind-card-studio/projects` | 카드 렌더러 프로젝트·일러스트 | 원본 JSON/Data URL |
| `duelmind-card-studio-assets/packs` | 렌더러 프레임·폰트 | 원본 JSON/Data URL |
| `유희왕_DESIGN_LAB_자료실/files` | YDK/TXT/CDB/Lua 등의 원본 파일 | Blob 바이트 원형 보존 |
| `ygo-studio-shared-media-v1/images` | 공통 이미지 ID 인덱스 | Blob 원형 보존 |
| `localStorage` 지정 키 | 공통 카드·덱, ART LAB 설정, PSH 관제 기록, 디자인 랩 덱 조건, 스튜디오 로컬 예비 원장 | 문자열 그대로 보존 |

## 제외되는 항목

- 브라우저 Origin이 다른 `127.0.0.1:5173` 또는 구형 GitHub Pages 주소의 저장 데이터: 보안 정책상 원격 접근 불가. 기존 로컬 렌더러 자료 이전은 사용자가 보류한 상태이므로 이번 패치에서 변경하지 않는다.
- 이미지 연구소에서 아직 파일로 내려받지 않은 일시적 캔버스, 로컬 PC의 실제 EDOPro/CDB/Lua 원본, 파일 경로만 기록된 PSH 실제 리플레이.
- 별도 `ygo-studio-migration-v1` 원본 보관함의 대용량 바이너리: 같은 ‘기존 사이트 데이터 이전’ 센터의 **원본 전체 ZIP 내보내기** 기능으로 따로 내려받는다.
- 사용자가 사용한 다른 Origin의 IndexedDB 데이터와 미공개 브라우저 저장소. V2.7 ZIP이 모든 PC 자료를 포괄한다고 주장하지 않는다.
- 암호화 기능은 이번 패치에 없다. ZIP에 원문/로그/이미지 등이 포함될 수 있으므로 안전한 위치에 보관하고 공개 저장소에 업로드하지 않는다.

## 복원 절차

1. 통합 사이트 → **기존 사이트 데이터 이전** → **현재 통합 자료 ZIP 다운로드**.
2. ZIP을 PC에 보관. 필요하면 다른 브라우저에서 `통합 백업 ZIP 검사·복원`을 선택해 검증.
3. 카드/일러스트/덱/PSH 등 복원할 종류별로 신규·기존 레코드 수를 확인. 본인이 확인창에서 승인한 항목만 신규로 추가.
4. 기존 키와 내용이 다른 경우에도 자동 덮어쓰지 않는다. 해당 작업실의 기존 JSON 백업 및 개별 원문 검토가 필요.
5. 원본 파일과 카드 프레임·이미지가 실제로 열리고, YDK 메인·엑스트라·사이드 및 PSH 원본 기록이 유지되는지 직접 확인.

## 회귀 검증

- Vitest 및 기존 Chromium 전체 회귀 테스트가 통과한 코드만 정식 병합.
- 백업 ZIP의 카드 메타·덱·DESIGN LAB Blob이 정확히 보존되는지, 각 파일의 SHA-256이 일치하는지 검사.
- 없는 공통 카드 데이터만 복원하고 기존 디자인 랩 Blob을 덮어쓰지 않는지 검사.
- 변조된 ZIP의 해시 검증 실패 시 복원 버튼을 표시하지 않고 현재 저장 데이터를 유지하는지 검사.
- 동일 카드 ID의 이미지 연결 중복이 기존 원본과 공유 이미지를 변경하지 않는지 확인.
- 실전 EDOPro AI 경기 완주나 MSG16 교착 해결로 오인하면 안 된다.
