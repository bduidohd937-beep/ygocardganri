# YGO STUDIO V2.7.1 — 백업 ZIP 안전 검사 및 복원 호환성

## 패치 방향

V2.7 백업·복원의 사용자 데이터 우선 정책을 유지하면서, 악의적인 ZIP 및 기존 IndexedDB 업그레이드에 대비한다. 기존 카드·이미지·덱·PSH 데이터 스키마, URL, CDB/Lua, 실전 AI 엔진을 수정하지 않는다.

## 변경

1. **압축 폭탄 방어:** ZIP 로딩 시 전체 CRC 강제 해제로 발생하던 압축 전량 해제를 비활성화한다. 압축 엔트리의 중앙 디렉터리에서 예상 압축 해제 크기·엔트리 수·합산 크기를 먼저 검증하고, 각 파일을 청크 단위로 해제하며 실제 결과가 용량 제한을 초과하면 즉시 중단한다.
2. **무결성 유지:** 기존 SHA-256과 원본 크기 대조를 그대로 적용한다. CRC를 대신하여 *등록된 모든 레코드와 Blob에 대한 해시 검증*을 수행한다. SHA-256은 무결성 검사이며 작성자 인증·전자서명이 아니다.
3. **조작 복원 차단:** 같은 파일 경로뿐 아니라 동일한 (저장소,키)를 이중 등재한 ZIP도 미리보기 전에 거부한다. ID를 키로 쓰는 객체는 백업 목록의 ID와 객체 내부 ID 일치를 복원 전에 확인한다.
4. **IndexedDB 버전 호환성:** 기존 데이터베이스의 버전을 강제로 1로 열지 않는다. 이미 다른 도구가 버전 2 이상으로 올린 DB에서도 기존 키는 보존하고 신규 데이터만 추가한다.
5. **기존 정책 유지:** Origin 간 자동 수집 금지, 사용자 확인 후 신규만 복원, 원본 보관함 별도 저장 및 ZIP 암호화 미지원.

## 회귀 테스트

- Chromium: 중앙 디렉터리에 60 MiB 단일 항목이 선언된 ZIP을 복원 미리보기 전에 차단.
- Chromium: 경로만 변경한 동일 저장소·키의 중복 등록 차단.
- Chromium: 버전 3으로 올라간 DESIGN LAB IndexedDB에 누락된 YDK Blob만 복원.
- V2.7 기존 SHA-256 손상 ZIP 거부와 원본 보호 테스트, 프로젝트/이미지 통합 테스트를 모두 재실행.

## 한계

- ZIP은 비암호화이며, 서명 기반 신뢰 검증 기능은 없다. 출처 불명 ZIP 복원은 권장하지 않는다.
- 브라우저의 ZIP 파서·압축 해제 라이브러리 자체 취약점은 라이브러리 업데이트와 별도 검수가 필요하다.
- 통합 백업은 원본 보관함의 대용량 파일과 다른 Origin의 브라우저 데이터를 포함하지 않는다.
