# YGO CARD STUDIO

유희왕 오리지널 커스텀 카드 제작·검수·기록관리 플랫폼.

> **UI/UX V1.0 — C안**: 카드 아트 갤러리 × 카드 개발 워크벤치. 현재는 최초 구현 버전(Alpha 0.1)입니다.

## 이번 구현

- 《종언성서 — 녹투르나》 및 《무명성서》 최초 데이터셋: 다섯 세계, 레벨 4 아벨 5종, 진화 단계 자리 10개, 공통 기본형 1장
- 프로젝트 홈·테마 갤러리·세계별 계보·카드 목록·카드 작업실·규칙/밸런스/EDOPro 상태 표시
- 카드 정보 편집, 미승인 효과 제안 및 명시적 승인/반려, 전체 변경 기록
- IndexedDB 우선 로컬 자동 저장, localStorage 폴백, JSON 백업/가져오기
- 카드 디자인 미첨부 시 **실제 카드 이미지 대신 '미첨부' 표시** (AI 시안 이미지를 승인본으로 속이지 않음)
- 작업 가능한 버튼과 아직 만들지 않은 기능을 구분한 화면
- TypeScript 및 단위 테스트 + GitHub Actions CI

## 아직 구현하지 않은 기능

- CDB/Lua/이미지/YDK/ZIP 실제 업로드 및 카드 ID 매칭(P2)
- Lua 정적 분석 및 엔진 실행, EDOPro 자동 테스트(P4/P6)
- 클라우드 계정/다기기 동기화, 실제 릴리스 출력(P7)
- 기존 독립형 HTML V2 백업 마이그레이션(별도 검증 필요)

## 저장 안전 원칙

1. 확정 효과 원문은 제안 등록만으로 바뀌지 않고, 승인 시에만 갱신됩니다.
2. 카드의 승인·OCG 검토·밸런스·CDB·Lua·듀얼 검증은 서로 다릅니다.
3. 파일을 업로드하거나 실제 시험하지 않았으면 상태를 '미확인'으로 유지합니다.
4. 현재 자료는 **사용자 브라우저에만 저장**됩니다. 중요한 변경은 JSON으로 백업하세요.
5. 코드는 이 저장소, 기존 커스텀 카드 원본은 별도의 소스 저장소로 분리합니다.

## P2 — 전체 테마·파일 센터

- 《종언성서 — 녹투르나》는 첫 번째 시드 테마이며, **테마 라이브러리에서 새 테마를 등록할 수 있습니다.**
- 파일 센터에서 테마를 선택하여 CDB(SQLite), Lua, YDK, 카드 ID 이미지, ZIP을 분석합니다. CPU 비용이 큰 파싱은 Web Worker에서 수행하고 중단할 수 있습니다.
- 가져오기 검토 → 원본 보관 확정. 카드 ID 충돌·중복·미등록 참조를 보고하며 **어떤 원문도 자동 승인·덮어쓰기하지 않습니다.**
- 파일 원본은 브라우저의 별도 IndexedDB에 저장됩니다. 기존 V1 카드·승인 데이터는 별도 저장소에 그대로 보관합니다.
- **중요:** JSON 카드 백업에 CDB/Lua/이미지 등의 바이너리가 포함되는 것은 아닙니다. 원본은 별도 보관하세요.
- 새 테마의 CDB 카드 텍스트는 업로드 원문 증거로 남으며, P3 카드 작업실에서 제안·승인·이력과 연결합니다.
- ZIP 해제 파일 수·경로·압축률·총량 제한, Lua 실행 금지, 입력 포맷 검증, 사용자 승인 절차를 사용합니다.

## P3: 통합 카드 작업실

CDB를 읽은 외부 테마 카드도 카드 ID별 작업실에서 원본 효과 후보, Lua, 이미지, 미승인 제안, 명시 승인, OCG/밸런스/EDOPro 검수 상태, 변경 이력을 관리한다. 《녹투르나》 16개 설계 문서와 외부 파일 기록은 변경하지 않으며, 같은 ID라도 테마마다 별도 기록으로 보존한다.

- 카드 라이브러리에서 아래쪽 **외부 테마·파일 연결 카드** 목록 또는 파일 센터의 카드 ID를 클릭하여 진입
- CDB 원문 → *미승인 제안* → 차이 비교 → 명시 승인 시에만 확정 효과 반영
- 검수 완료/승인 변경에는 사용자 근거 입력 필요. Lua는 읽기 전용 미리보기이며 실행하지 않음
- 업로드 자료의 바이너리 백업은 JSON과 **별도**. P1 녹투르나/ P3 외부 테마 작업 문서도 각각 JSON 내보내기·복원.

[세부 규칙](./문서/P3_통합_카드_작업실_설계.md)


## P4 — 정적 카드 오류 분석기

- 좌측 **오류 분석** 메뉴에서 테마를 선택하고 검사를 실행하거나, 업로드 카드 작업실의 **정적 오류 분석** 탭에서 해당 카드만 검사할 수 있습니다.
- CDB 원본 간 이름/효과 충돌, 승인 원문과 CDB 차이, Lua 연결 누락/중복 및 `initial_effect` ID 불일치를 확인합니다.
- 카드명 기준 1턴 제한/대상 지정/특수 소환/콜백 함수 의심은 **검토 후보**로만 표시하며, OCG 규칙 위반을 자동 확정하지 않습니다.
- 항목별 규칙 ID·원본 출처·근거·권고를 표시하고 수동 검토 기록을 별도 저장하며 JSON 보고서를 내보낼 수 있습니다.
- 최대 200장/회, 카드별 Lua 원본 최대 3개/128KiB 검사이며 미검사 범위를 명시합니다. 정적 분석은 Web Worker에서 실행하고 중단할 수 있습니다.
- 발견 항목이 0건이더라도 OCG/EDOPro 검증 완료를 의미하지 않으며 업로드된 Lua를 실행하거나 기존 승인 효과·CDB·Lua 원본을 수정하지 않습니다.

[분석 규칙과 한계](./문서/P4_정적_오류_분석_설계.md)
## P4.1 — Lua AST 정밀 분석
- Lua 5.3 구문 AST로 함수·콜백·등록 흐름을 점검하고, 파서 불일치는 **정적 의심**으로 표시합니다.
- 초기화 함수 카드 ID와 일부 횟수 제한 문구는 **수정 전후 검토안**을 제공할 수 있습니다.
- 원본 SHA256 검증 후 수동 근거 승인으로만 별도 `검토안_c<ID>.lua` 파일을 내보냅니다.
- 기존 원본 파일 및 효과 승인 상태는 변경하지 않습니다. EDOPro 구현·검증은 별도 절차입니다.
- 상세: [P4.1 설계](문서/P4.1_Lua_AST_수정제안_설계.md)

## P4.2 — 효과 원문 ↔ Lua 4단계 대조

- 오류 분석 화면에서 카드별 **발동 조건·코스트·대상·효과 처리**를 CDB 또는 승인 원문과 Lua AST로 나란히 비교합니다.
- 각 단계는 **구조 발견 / 구현 검토 필요 / 판별 불가 / 문구 미인식**으로 표시합니다. 호출 코드 존재는 올바른 처리나 엔진 실행 성공의 증명이 아닙니다.
- CDB 간 원문이 충돌하면 확정 기준을 임의로 고르지 않습니다. 다중 번호 효과·다중 Lua·외부 헬퍼·원본 누락도 보수적으로 판별합니다.
- 검토 대상은 `ALIGN_*_REVIEW` 정적 의심으로 별도 표시합니다. 원본·승인 텍스트와 검증 완료 상태는 자동 변경하지 않습니다.
- 세부 규칙: [P4.2 효과 원문·Lua 대조 설계](문서/P4.2_효과원문_Lua_대조_설계.md)

## P4.3 — ①·②·③ 효과별 Lua 연결 지도

- 카드 텍스트의 번호 효과를 분리하고 Lua AST에서 `initial_effect`, 등록 이펙트(`e1`, `e2` 등), `SetOperation`, 실제 콜백의 `Duel.*` 호출을 대조합니다.
- **Lua 변수 번호와 카드 효과 번호는 자동으로 동일시하지 않습니다.** 직접 처리 함수의 고유한 근거가 있을 때만 연결 후보로 표시합니다.
- 여러 효과가 같은 동작을 사용하거나 `Clone()`, 복수 Lua·보조 헬퍼·CDB 충돌이 발견되면 **판별 불가**로 남깁니다.
- 효과 번호별 발동 조건·코스트·대상·처리 단계에서 확인된 코드 구조와 검토가 필요한 부분을 표시하고 JSON 정적 보고서에 포함합니다.
- 기존 P4/P4.1/P4.2 분석을 유지하며 분석용 Lua AST는 Worker 안에서 카드별로 최대 3개만 캐싱합니다. 원본 Lua·CDB·승인 효과·EDOPro 검증 상태를 변경하지 않습니다.
- 사용: **파일 센터 → CDB/Lua 업로드 → 카드 작업실 → 정적 오류 분석 → 번호 효과별 Lua 연결 지도**
- 한계 및 테스트: [P4.3 번호별 효과/Lua 연결 설계](문서/P4.3_번호별효과_Lua콜백_연결_설계.md)

## P5 — 멀티테마 덱 연구실

- **덱 연구실** 메뉴에서 가져온 YDK의 메인·엑스트라·사이드 덱을 확인한다.
- 원본과 분리된 연구안을 생성하고, 카드별 **초동·전개보조·말림·패트랩**을 직접 지정한다. CDB 카드명이 없으면 미확인 표시.
- 메인 덱 매수 조정(40~60장 비교), 초기 패 5/6장의 **정확한 비복원 추출 확률**과 원본 대비 변화량을 계산한다.
- 역할 태그가 없으면 0%라고 주장하지 않는다. 전개 루트/실제 소환 성공/금제 적법성/승률은 아직 계산 대상이 아니다.
- 연구안은 독립 IndexedDB에서 리비전을 보호하며 별도 JSON 백업·복원 및 YDK 내보내기를 제공한다. **업로드 YDK·CDB·Lua·이미지 원본은 수정·동봉하지 않는다.**
- [계산 기준과 사용 한계](문서/P5_덱연구실_설계와_확률검증.md)

## P5.1 — 조합 초동 분석기

- **덱 연구실**에서 연구안을 생성하면 조합 분석기로 최대 4개 A 단독 또는 A+B 루트를 설정할 수 있다.
- 여러 루트는 OR로 합치며 중복 패를 한 번만 센다. A+B는 같은 ID가 포함돼도 서로 다른 실물 카드 **2장**이 필요하다.
- 특정 말림 카드 ID 동반/미동반 및 루트 실패 확률을 별도로 계산하고, 원본 YDK와 %p 차이를 비교한다.
- 계산식은 첫 패 5/6장의 비복원 무작위 추출이며 **실제 서치·소환·효과 조건을 통한 전개 성공률이 아니다.**
- P5 분석안 JSON 형식은 이전 버전과 호환되며 원본 YDK/CDB/Lua를 자동으로 수정하지 않는다.
- 상세: [P5.1 확률 및 검수 기준](문서/P5.1_조합초동_확률_검수기준.md)
