# YGO CARD STUDIO — 유희왕 커스텀 카드 통합 관리실

> 기획 단계 · V0.1 · 2026-11-11

이 저장소는 **웹앱 소스코드·화면·검수 로직·테스트·설계 문서**를 관리합니다. 사용자가 제작한 오리지널 테마의 카드 원문, CDB, Lua, 이미지, 덱, 세계관과 구현 이력을 한곳에서 연결하는 웹 스튜디오를 개발합니다.

## 목표
- 카드 설계부터 승인·OCG 표현 검수·EDOPro 스크립트 검증·덱 테스트·배포까지의 진행 상태를 추적
- 텍스트 원문, 제안, 구현 파일, 테스트 결과를 **서로 다른 자료**로 관리
- 확인되지 않은 정보는 '미확인'으로 표시하고 출처 없는 자동 확정 금지
- 제안→검토→승인→구현→테스트→릴리스 흐름 및 변경 이력 보존
- 초기 화면은 《종언성서 — 녹투르나》 / 《무명성서》의 기존 설계 정보를 기반으로 시작하되, 향후 모든 오리지널 테마를 수용하는 데이터 모델 사용

## 저장소 역할
- `ygocardganri` (이 저장소): 웹앱·문서·테스트·마이그레이션 코드
- `ygocustome` (기존 저장소): 원본으로 확인된 카드 자료 등 기존 소스 보존; 이 저장소에서 변경 시 무단 덮어쓰기 금지
- 대용량 원본/이미지/업로드는 추후 **별도 비공개 스토리지**로 분리 가능. GitHub 공개 저장소에 비공개 파일·토큰 업로드 금지

## 핵심 원칙
1. 카드 내부 키(UUID)와 EDOPro 카드 ID를 별도 저장한다. 카드 ID 중복은 오류로 보고한다.
2. 입력 CDB·Lua·이미지·YDK는 원본 해시/출처/업로드 시간 기록 후 연계하며 원본을 임의 수정하지 않는다.
3. '설계 승인', 'OCG 검수', 'Lua 통과', '실전 검증'은 각각 별도 상태다.
4. Lua 업로드 자체를 실행하지 않는다. 정적 검수와 격리된 EDOPro 테스트는 별도 경로로 처리한다.
5. 일러스트 승인과 카드 효과 승인 역시 독립된 상태다.
6. 모든 AI 수정 제안은 변경점(diff)과 근거를 보여준 뒤 사람의 명시적 승인을 받는다.
7. 사람 관리용 문서/이미지 묶음 이름은 한글 우선. 카드 이미지 파일명은 카드 ID, Lua는 `c<카드ID>.lua` 규칙 등 엔진 호환성을 따른다.
